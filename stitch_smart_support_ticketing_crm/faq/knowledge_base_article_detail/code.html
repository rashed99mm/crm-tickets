REST API Authentication & Token Management

By Sarah Jenkins
12 min read

This guide explains how to authenticate your application with the CommandCenter CRM REST API using OAuth 2.0 and API keys. Proper authentication is critical for securing customer data and maintaining system integrity.

info

Important Note

API Version 1 (v1) is officially deprecated as of October 2023. All new integrations must use v2. Existing v1 tokens will expire on March 31, 2024.

1. OAuth 2.0 Authorization Code Flow

For applications acting on behalf of a user, we recommend the standard Authorization Code grant type. This ensures that the user's credentials are never exposed to the client application.

  • Client ID: Unique identifier for your registered application.
  • Client Secret: Confidential string used to authenticate the client (do not share).
  • Redirect URI: The endpoint where the user is sent after authorization.

Generating Bearer Tokens

Once you have the authorization code, exchange it for an access token by making a POST request to the token endpoint.

POST /oauth/token HTTP/1.1
Host: api.commandcenter.io
Content-Type: application/x-www-form-urlencoded

grant_type=authorization_code&
code=AUTH_CODE_HERE&
redirect_uri=YOUR_REDIRECT_URI&
client_id=YOUR_CLIENT_ID&
client_secret=YOUR_CLIENT_SECRET

2. Personal API Keys

For internal scripts or single-user applications, you can generate a Personal Access Token (PAT) directly from your Account Settings.

  1. Navigate to System Settings > API & Integrations.
  2. Click Generate New Token.
  3. Select the required scopes (e.g., tickets:read).
  4. Copy the generated token immediately. It will not be shown again.
